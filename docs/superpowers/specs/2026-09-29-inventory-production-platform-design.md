# 제조업 재고·생산 연계 플랫폼 설계

## 목적

신규 사업 담당자가 고객사별 제조 재고관리 구조를 시스템 안에서 운영·분석할 수 있도록 한다. 시스템이 기준 데이터가 되며, 생산계획·출하계획·BOM·재고거래·발주·입고를 연결해 자재 부족 위험과 발주 필요량을 자동 계산한다. Excel은 초기 데이터 마이그레이션, 대량 입력, 분석 결과 내보내기를 위한 보조 수단으로 제공한다.

## 사용자와 범위

주 사용자는 사내 신규 사업 담당자와 고객사의 재고·생산 담당자다. 프로젝트마다 여러 고객사를 둘 수 있으며, 선택된 고객사의 재고·생산 데이터만 분석한다.

이번 범위는 다음과 같다.

- 품목 및 생산 관련 기준정보 입력
- 생산계획 및 출하계획 입력
- BOM 등록과 완제품-부품 관계 관리
- 입고·출고·생산투입·조정 재고거래 입력
- 공급사 발주 및 입고예정 입력
- 생산계획과 BOM을 기반으로 한 자재소요량 계산
- 현재고·발주잔량·입고예정량을 반영한 순부족량 계산
- 안전재고·리드타임 기반 발주위험 및 부족예상일 표시
- 거래·계획·계산 결과를 고객사별로 저장
- Excel 가져오기·내보내기 및 업로드 검증
- 재고·생산 KPI와 ROI 계산에 사용할 결과 제공

다음 범위는 후속으로 둔다.

- ERP/MES/WMS 실시간 API 연계
- 바코드·RFID·모바일 현장 입력
- 공급사 포털 및 자동 발주 전송
- 품질·LOT·공정 추적의 전체 기능
- 외부 고객 계정·과금·권한 정책

## 핵심 원칙

### 시스템이 기준 데이터

Excel의 잔량을 그대로 저장하지 않는다. 현재고는 기초재고와 거래이력에서 계산한다.

```text
현재고 = 기초재고 + 입고 + 생산완료 - 출고 - 생산투입 - 폐기 ± 재고조정
```

사용자가 현재고를 직접 수정하는 경우에는 조정거래로 기록해 변경자·사유·시점을 남긴다.

### 입력 즉시 재계산

생산계획, BOM, 재고거래, 발주, 입고예정이 변경되면 선택 고객사의 계산 결과를 즉시 재계산한다. 서버가 없는 현재 정적 MVP에서는 저장소 변경 후 순수 계산 함수를 호출하는 방식으로 구현하고, 이후 API·DB로 교체할 수 있도록 계산 로직과 화면을 분리한다.

### 고객사 데이터 격리

모든 생산·재고 데이터는 `projectId`와 `customerId`에 귀속된다. 고객사 선택을 바꾸면 품목·BOM·계획·거래·분석 결과가 함께 바뀌며 다른 고객사의 데이터가 섞이지 않는다.

## 데이터 모델

```text
Project
 └─ Customer
     ├─ InventoryItem
     ├─ InventoryTransaction
     ├─ ProductionPlan
     ├─ ShipmentPlan
     ├─ BomLine
     ├─ SupplierOrder
     └─ SupplierReceipt
```

### InventoryItem

- `id`, `code`, `name`, `type` (완제품/부품/원자재)
- `unit`
- `openingStock`
- `safetyStock`
- `dailyUsage`
- `leadTimeDays`
- `unitCost`
- `supplierId`

### InventoryTransaction

- `id`, `itemId`, `type` (입고/출고/생산투입/생산완료/조정/폐기)
- `quantity`, `date`, `note`
- `sourceType` (수기/생산계획/발주/Excel)

### ProductionPlan

- `id`, `date`, `itemId`, `lineId`, `plannedQuantity`, `status`

### ShipmentPlan

- `id`, `date`, `itemId`, `plannedQuantity`, `customerName`

### BomLine

- `id`, `parentItemId`, `componentItemId`, `quantityRequired`, `effectiveFrom`, `effectiveTo`

### SupplierOrder / SupplierReceipt

- 발주: 공급사, 품목, 발주일, 예정입고일, 수량, 상태
- 입고: 발주 연결값, 입고일, 입고수량, 검사상태

## 계산 규칙

### 재고 계산

품목별 거래를 합산해 현재고를 계산한다. 화면에 저장된 `currentStock`은 표시용 캐시로 사용할 수 있지만 거래이력과 불일치하면 계산 결과를 우선한다.

### BOM 소요량

```text
부품 필요량 = 생산계획 수량 × BOM 사용량
```

기간별 생산계획을 합산하고, 같은 부품이 여러 완제품에 사용되면 부품 기준으로 합산한다.

### 순부족량

```text
순부족량 = 총 필요량 + 안전재고 - 현재고 - 발주잔량 - 입고예정량
```

순부족량이 0보다 크면 발주 필요 대상으로 표시한다.

### 부족예상일과 위험도

```text
소진예상일수 = 현재고 / 평균일사용량
재발주점 = 안전재고 + 평균일사용량 × 리드타임
```

위험도는 다음 우선순위를 따른다.

1. 생산일 이전 순부족 발생: 긴급
2. 재발주점 이하: 발주 검토
3. 안전재고 이하: 주의
4. 충분한 재고: 정상

일사용량이 0이면 소진예상일을 계산하지 않고 별도 상태로 표시한다.

## 화면 흐름

```text
고객사 선택
 → 재고·생산 대시보드
 → 기준정보
 → 생산/출하계획
 → 재고거래
 → BOM·자재소요
 → 발주·입고
 → 위험·ROI
```

초기 화면은 기존 고객사 분석 화면과 동일한 고객사 선택 구조를 유지하고, 고객사 선택 후 `재고관리 플랫폼` 영역으로 진입한다.

대시보드에는 다음을 표시한다.

- 품목 수, 총 재고수량, 재고금액
- 발주위험 품목 수
- 생산일 이전 부족 품목 수
- 오늘의 생산·출하계획
- 입고지연 및 미입고 수량
- 최근 재고거래

## Excel 기능의 위치

Excel은 핵심 입력 흐름이 아니다. 다음 메뉴로 제공한다.

- 템플릿 다운로드
- 품목/BOM/계획/거래 일괄 가져오기
- 중복 품목·미등록 BOM·잘못된 날짜·음수 수량 검증
- 오류 행 다운로드
- 계산 결과와 ROI 보고서 내보내기

가져온 데이터도 일반 입력과 같은 저장 모델과 계산 함수를 사용한다.

## ROI와 KPI

플랫폼은 다음 KPI 계산에 필요한 원천 데이터를 제공한다.

- 재고금액
- 안전재고 이하 품목 수
- 품절·생산중단 발생건수
- 재고 커버리지
- 긴급발주 건수
- 공급사 납기준수율
- 계획 대비 생산달성률
- 수기 재고처리시간

ROI는 고객별 입력값으로 계산한다.

```text
연간 효과 = 재고절감액 + 긴급구매절감액 + 운송비절감액
          + 수기처리절감액 + 생산중단손실감소액

ROI = (연간 효과 - 연간 운영비) / 초기 구축비 × 100
```

계산되지 않은 금액은 임의 추정하지 않고 입력 필요 상태로 표시한다.

## 오류 처리와 신뢰성

- 존재하지 않는 품목에 대한 거래는 저장하지 않는다.
- BOM의 부모·부품 품목이 없으면 저장하지 않는다.
- 생산계획과 출하계획의 날짜·수량 형식을 검증한다.
- 음수 수량은 조정 유형을 제외하고 허용하지 않는다.
- 계산 결과가 없는 경우 빈 상태와 입력 안내를 표시한다.
- Excel 업로드 오류는 전체 반영 전에 행 단위로 보여준다.

## 테스트 기준

- 품목별 거래 입력 후 현재고가 정확히 계산된다.
- 생산계획과 BOM으로 부품 필요량이 계산된다.
- 현재고·발주·입고예정을 반영한 순부족량이 계산된다.
- 재고·생산 데이터가 고객사별로 격리된다.
- 입력 변경 후 대시보드가 즉시 갱신된다.
- Excel은 보조 입력으로만 사용되며 동일 계산 결과를 만든다.
- 새로고침 후 저장된 데이터와 계산 결과가 복원된다.
- 기존 고객사 분석·ROI·PoC 기능이 깨지지 않는다.
