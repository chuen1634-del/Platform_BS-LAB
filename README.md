# Platform BS-LAB

고객사 정보를 바탕으로 신규 사업 기회를 발굴하고, 제조업 재고관리 솔루션 제안까지 연결하는 사내 업무 도구입니다.

이 프로젝트는 영업 전 사전 분석과 고객 미팅 이후의 재고관리 진단을 하나의 흐름으로 묶습니다. 회사소개서만 있는 초기 단계부터 현장 인터뷰와 운영 데이터를 확보한 단계까지 같은 프로젝트 안에서 고객별 자료와 분석 결과를 관리할 수 있습니다.

## 이 시스템이 해결하는 업무

- 프로젝트 하나에 여러 고객사를 등록하고 고객사를 선택해 분석
- 미팅 전 회사소개서, 홈페이지 메모, 공개자료 등으로 기초 가설 작성
- 미팅 후 인터뷰 메모를 As-Is, Pain Point, To-Be 후보로 구조화
- 품목, 재고거래, 생산계획, BOM, 공급사 발주, 입고를 고객사별로 관리
- 입력한 거래와 생산계획을 기준으로 현재고, 자재소요량, 발주잔량, 순부족량, 발주위험을 자동 계산
- 분석 결과를 재고관리 솔루션 제안, ROI 가설, PoC 범위로 연결
- As-Is/To-Be/ROI가 부족한 경우에도 확인 필요 항목, 표준 To-Be, ROI 산정용 입력값, PoC 초안을 제시

## 화면 및 모듈

### 홈

처음 사용하는 담당자가 업무 목적을 이해할 수 있도록 고객사 분석, 재고관리 시스템, Solution 제안 모듈과 사용 예시를 안내합니다.

### 고객 분석

프로젝트와 고객사를 선택한 뒤 다음 자료를 고객사별로 입력합니다.

- 회사소개서 또는 회사 기본 정보
- 미팅 메모와 현장 인터뷰 내용
- 운영 데이터, Excel 요약, 참고 링크
- 사용 중인 시스템과 업무상 문제

자료를 저장하면 업종, 업무 단계, Pain Point, 가설, 확인 질문, 참고 사례를 정리하고 As-Is/To-Be, ROI, PoC 정보를 누적할 수 있습니다.

초기 자료가 없는 경우에도 `자료 없이 시작`을 선택해 빈 프로젝트를 만들 수 있습니다. 이때 시스템은 회사소개서 기반 분석이 아니라 미팅에서 확인해야 할 질문 중심으로 시작합니다.

### 재고관리 시스템

고객사별로 재고 운영의 기본 데이터를 직접 입력하는 운영형 MVP입니다.

| 입력 영역 | 주요 내용 |
| --- | --- |
| 품목 마스터 | 원자재·부품·완제품, 단위, 안전재고, 리드타임, 단가 |
| 재고거래 | 입고·출고·조정, 수량, 일자, 사유 |
| 생산계획 | 생산 품목, 생산 수량, 계획일 |
| BOM | 완제품별 필요 자재와 소요 수량 |
| 공급사 발주 | 발주 수량, 납기, 상태 |
| 입고 | 발주 기준 입고 수량, 일자 |

입력 후 고객사별로 다음 값을 자동 산출합니다.

```text
현재고 = 기초재고 + 입고 - 출고 ± 조정
자재소요량 = 생산계획 수량 × BOM 소요량
순부족량 = max(0, 자재소요량 + 안전재고 - 현재고 - 발주잔량)
발주위험 = 부족 여부 + 납기 임박 여부 + 리드타임 정보
```

Excel은 첫 번째 입력 방식이 아닙니다. 필요할 때 초기 마이그레이션, 대량 입력, 고객 데이터 구조 확인, 결과 내보내기를 위한 보조 경로로 확장합니다.

### Solution 제안

고객 분석과 재고관리 데이터를 함께 보고 다음 내용을 제안서 형태로 정리합니다.

- 고객 상황과 핵심 Pain Point
- As-Is 업무 흐름과 리스크
- To-Be 재고관리 플랫폼 구조
- 자동 계산 및 업무 연계 범위
- ROI 산정 방법과 필요한 추가 데이터
- PoC 범위, 성공 기준, 다음 미팅 질문

재고관리 데이터가 입력되면 품목, 생산계획, 부족 자재, 납기 위험이 제안 근거에 반영됩니다. 아직 수치가 부족하면 결과를 임의로 확정하지 않고 `확인 필요`, `표준 가설`, `측정 계획`으로 구분합니다.

## 권장 사용 흐름

1. 홈에서 `고객 분석` 또는 `재고관리 시스템`을 선택합니다.
2. 프로젝트를 만들고 고객사를 추가합니다.
3. 미팅 전이면 회사소개서나 기본 정보로 분석을 시작합니다.
4. 미팅 후에는 인터뷰 메모를 추가하고 `미팅 정보 연결 가이드`에서 재고관리 입력 항목으로 변환합니다.
5. 품목과 재고거래를 먼저 입력한 후 생산계획, BOM, 발주, 입고를 순서대로 보완합니다.
6. 자동 계산된 부족량과 발주위험을 확인합니다.
7. Solution 제안 화면에서 As-Is/To-Be, ROI 가설, PoC를 완성합니다.

## ROI 산정 원칙

시스템은 고객이 제공하지 않은 절감액이나 효과를 사실처럼 만들지 않습니다. 다음 입력값이 확보될 때만 수치형 ROI를 계산합니다.

- 재고 금액과 평균 보유기간
- 재고조사 및 수기입력에 쓰는 시간
- 긴급 발주, 생산 지연, 결품의 발생 횟수와 비용
- 도입비, 운영비, 예상 개선율

기본 구조는 다음과 같습니다.

```text
연간 기대효과 = 재고자금 절감 + 업무시간 절감 + 결품·긴급대응 손실 감소
순효과 = 연간 기대효과 - 연간 운영비 - 도입비 상각분
ROI = 순효과 / 총투자비
```

수치가 부족한 단계에서는 금액 대신 측정할 KPI와 PoC에서 확인할 데이터 수집 계획을 제시합니다.

```powershell
npm run dev
```

브라우저에서 `http://localhost:4173`을 엽니다.

## 테스트

```powershell
npm test
```

현재 테스트는 분석 모듈, 재고 계산, 고객사별 저장소, Solution 제안 생성, 미팅 메모와 재고관리 항목의 연결 로직을 확인합니다.
